## Dataset and split

- Official CIFAR10 (10 classes, 50,000 train images, 10,000 test images),
  obtained as the official `cifar-10-python.tar.gz` with MD5 verified equal to
  torchvision's published `tgz_md5` (`c58f30108f718f92721af3b95e74349a`).
  `make_split.py` (and torchvision's loader) download it automatically;
  the exact bytes used are the official release.
- The 50,000 official training images are split into a **stratified 45,000
  train / 5,000 validation** split with `random_state=260004`
  (`sklearn.model_selection.train_test_split`, stratified, `test_size=5000`).
  Indices are saved in `split/cifar10_split_seed260004.npz` and used by every
  experiment. Class counts: 4,500/450 per class (train/val).
- The official **test set is used only for final reporting**, never for tuning.
- No data augmentation is used anywhere.

## Reproducing everything from scratch

Run from the repository root. Each script is deterministic (seed 260004) and
regenerates its outputs under `results/` and `figs/`.

```bash
# 0. one-time: CIFAR10 download + fixed split
python scripts/make_split.py            # downloads CIFAR10 into data/

# Q1
python scripts/q1a_comparison.py        # MLP-base / MLP-reg / MLP-small
python scripts/q1b_memorization.py      # true-labels vs random-labels MLP

# Q2
python scripts/q2a_cnn_vs_mlp.py        # fair CNN vs MLP comparison
python scripts/q2b_permuted.py          # same models, fixed pixel permutation
python scripts/q2c_translation.py       # test-time translation sweep

# Q3
python scripts/q3a_autoencoders.py      # three conv AEs (bottlenecks 32/256/1024)
python scripts/q3a_recon_grid.py        # clean-AE recon grid (DAE grid skipped until Q3b runs)
python scripts/q3b_denoising.py         # Gaussian-noise DAE + fixed CNN classifier
python scripts/q3a_recon_grid.py        # second run: also writes the DAE recon grid
python scripts/q3c_representations.py   # frozen linear probes vs reconstruction

# Q4 (bonus)
python scripts/q4_features.py           # cache fixed representation + 9k SVM subset
# The 15 (kernel, C) fits are independent tasks; run them in any order/parallel.
# Note: results/q4/sweep_seeded.json preserves verbatim the rows computed in the
# first (sequential) pass - the five linear cells and the RBF C=0.01 cell (the
# linear C=100 cell alone takes ~1 core-hour on an M2). Every other cell is
# (re)computed by the commands below; --finalize then assembles sweep.csv,
# applies the validation-only selection rule, and evaluates the selected
# model on the official test set exactly once.
for KERNEL in linear rbf poly; do for C in 0.01 0.1 1.0 10.0 100.0; do python scripts/q4a_svm_sweep.py --kernel $KERNEL --C $C; done; done
python scripts/q4a_svm_sweep.py --finalize
python scripts/q4b_hard_pairs.py        # support vectors & near-boundary test analysis
python scripts/q4c_clustering.py        # KMeans/GMM method selection + ARI/NMI/contingency

# figures + report
python scripts/make_figures.py
python report/build_report.py --commit <hash-from-page-1-of-the-report>   # writes report/main.pdf
```

Runtime on Apple M2 (MPS): roughly 1.5–2.5 hours in total (the SVM sweep in Q4(a) is the slow part). On CPU, expect several hours.

## Reproducing the report

The report's page 1 shows the hash of the freeze commit (the state that produced
the results, figures and this report). To rebuild `report/main.pdf` from that
exact state:

```bash
python report/build_report.py --commit <freeze-hash-from-page-1-of-the-report>
```

`report/main.pdf` is added to the repository by the commit after the freeze
(the freeze commit itself is not modified). The rebuilt PDF's pages 2..N are
identical to the committed one; only the PDF's internal creation timestamp
differs.

## Layout integrity notes

- `q2-cnn` (Q2a) is reused as the **fixed CNN classifier** in Q3(b) — stated in
  the report.
- The **validation-selected clean AE** from Q3(a) is reused in Q3(b) (baseline),

  and logged separately for their own comparisons.

  recorded in the scripts (docstrings) and in each `metrics.json`.
